## 3. 발견한 문제

### 문제 ① 속도가 그때그때 크게 다르다
- 같은 글 요약이 **약 1분 30초 / 47초**, 같은 회의록 할 일 추출은 2분 30초 넘게 걸리고 실패. 무료 API 라 사용자가 몰리면 느려지는 것으로 보임.
- 추론 모델이라 답 쓰기 전에 생각하는 글도 쓰는데, 무료 API 출력 속도가 느림(초당 약 20토큰).
- **우리 코드로 해결할 수 없는 부분.** 시연에서 몇 분 기다리거나 실패할 위험.

### 문제 ② 할 일 추출이 할 일이 많으면 실패한다
- 오류 원인: AI 가 쓸 수 있는 최대 분량(4,096토큰)을 **생각하는 글에 다 써 버려서** 답(할 일 목록)이 중간에 잘림.
- 화면 안내는 "범위를 줄여 다시 시도"이고, 이번 테스트는 이미 최소 범위(10개)였음.

### 문제 ③ 실제 채팅에서 담당자를 찾을 수 있는지 확인 필요 (모델과 상관없음)
- 요약·할 일 추출은 AI 에 **메시지 본문**을 보내고, 보낸 사람 이름은 함께 보내지 않습니다.
- 할 일 추출에는 "'제가', '내가'로 사람을 추측하지 말 것"이라는 안전 규칙이 있어서,
  실제 채팅(한 명씩 말하기)에서는 담당자가 빈칸으로 나올 수 있습니다.
- 이번 테스트는 회의록 안에 "박준호: …"처럼 이름이 적혀 있어 이 부분을 확인하지 못했습니다.

### 문제 ④ 요약에 담당자 이름이 빠진다
- 할 일·기한은 정확하지만 "누가"가 없음. (③ 을 고치면 같이 나아질 가능성 높음)

## 4. 오늘 정할 것

### 안건 1. AI 모델 — 어떻게 할까?

| 선택지 | 장점 | 단점 / 필요한 것 |
|---|---|---|
| **A. EXAONE 유지** | 추가 비용·작업 없음 | 느림·들쭉날쭉·할 일 추출 실패. 시연 위험 |
| **B. 두 개 같이 두고 설정으로 전환 (추천)** <br>`AI_PROVIDER=exaone` ↔ `gemini` | 지금까지 만든 것 유지, 새 AI 가 이상하면 설정 한 줄로 되돌림 | Gemini API 키 발급(팀장, 무료 한도로 부족하면 결제 등록), E 작업 반나절 정도 |
| C. 새 모델로 완전 교체 | 코드 단순 | 되돌릴 길이 없음 |

- B 를 고르면 사용할 AI: **Google Gemini** — 빠른 **Flash 계열** 모델 권장. 정확한 모델 이름과 무료 사용 한도는 E 가 공식 문서에서 확인.
  - Flash 계열 중에는 기본으로 "생각하는 단계"를 켜 두는 모델이 있음 → 속도를 위해 생각 단계를 끄거나 최소로 줄이는 설정이 있는지 함께 확인.
- 새 패키지 없이 지금처럼 `fetch` 로 호출 가능 → `package.json` 변경 없음.
- 자동 전환("EXAONE 실패하면 Gemini 로")은 **비추천** — 4분 기다린 뒤에야 넘어가서 더 느리고 요금이 두 번 나갈 수 있음.

**결정:** ☐ A ☐ B ☐ C

### 안건 2. AI 에 보낸 사람 이름을 같이 보낼까? (문제 ③)
- 보내면: 실제 채팅에서도 담당자를 찾을 수 있음 (할 일 추출의 핵심).
- 고려할 점: 사람 이름이 **외부 AI 회사로 전송**됨. 사내 서비스 가정이므로 팀 동의 필요.
- 작업 크기: 작음 (서버에서 메시지 읽을 때 `profiles.name` 만 같이 가져오기).

**결정:** ☐ 보낸다 ☐ 안 보낸다

### 안건 3. 최대 대기 시간
- 현재 240초는 무료 API 가 느릴 때도 결과를 받을 수 있도록 E 가 여유 있게 잡은 값입니다.
- 모델을 바꿔 응답이 빨라지면, 그 속도에 맞춰 함께 조정할지 검토합니다.

**결정:** ☐ 240초 유지 ☐ 모델 결정 후 E 와 조정

### 안건 4. 시연 전략
- 시연 전에 **같은 채널로 미리 여러 번 돌려 시간 재기**.
- 오래 걸리거나 실패하면 → AI 기능은 **녹화 영상**으로, 실시간 시연은 채팅·스레드·검색·이동 위주.
- 기능의 원래 사용 방식대로 **계정 2~3개로 한 명씩 채팅**한 뒤 요약·할 일 추출을 다시 테스트.

**결정:** ☐ 실시간 시연 ☐ 녹화 영상 ☐ 둘 다 준비
