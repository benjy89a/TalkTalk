### 1. B-1 메시지 목록
- **설계부터 질문으로 정함**: 연속 메시지 5분 묶기, "오후 3:42" + 날짜 구분선, 빈 화면·실패 시 다시 시도 버튼.
- 불러오기 로직을 `useChannelMessages` 훅으로 따로 빼둠 → 이후 실시간·델타 동기화가 같은 파일에 자연스럽게 붙음.
- 🐞 **문제: 연속 메시지 사이가 빈 줄처럼 벌어짐**
  → 원인: 마우스를 올리면 보이는 숨은 시간("오전 10:42")이 좁은 칸에서 두 줄로 접혀 높이를 차지(46px).
  → 해결: 시간을 "10:42" 로 줄이고 한 줄 고정 → 28px.
- 🐞 **문제: 한글로 치고 Enter 하면 같은 메시지가 두 번 들어감**
  → 원인: 한글 조합 중 Enter 를 브라우저가 두 번 보냄.
  → 해결: 조합 중(`isComposing`) Enter 는 무시. → 계섭님이 직접 확인 ✅

### 2. B-2 메시지 전송 + 중복 방지
- 🐞 **문제: Enter 후 글이 뜨기까지 최대 2초, 목록이 깜빡임**
  → 원인: "저장 → 목록 전체 다시 불러오기" 를 차례로 기다림 (측정: 0.2~0.9초 + 0.5~1.0초).
  → 해결: **먼저 보여주고 나중에 확인**(낙관적 표시). Enter 즉시 흐리게 표시 → 저장되면 진하게. → **0.016초**로 단축.
- 입력창과 목록은 화면의 서로 다른 칸이라, 둘이 같은 데이터를 보도록 `outbox.ts` 공유 보관함을 만듦 (팀장님이 따로 이어줄 필요 없음).
- 중복 방지: `client_id` 는 처음 한 번만 만들고 재전송에도 그대로 → DB UNIQUE + `upsert(ignoreDuplicates)`.
- **일부러 실패시켜 검증**: 인터넷 끊김 흉내 → 재전송 3번 연타 → DB 1건 ✅ / 서버엔 저장됐는데 응답만 유실 → 재전송 → DB 1건 ✅

### 3. B-3 실시간 수신 + 카톡식 말풍선
- `messages` INSERT 를 채널 필터로 구독. 실시간 행에는 보낸 사람 이름이 없어서 프로필을 한 번 불러와 기억.
- 실시간 메시지가 저장 응답보다 먼저 오면 "보내는 중" + "저장됨" 두 번 보일 수 있음 → `client_id` 로 한쪽 제거.
- 위쪽을 읽는 중에 새 메시지가 오면 끌어내리지 않고 "새 메시지 n개 ↓" 버튼.
- 계정2로 보내서 검증: **0.4초** 안에 표시 ✅ (완료 조건 1초)
- 계섭님 요청으로 **카톡처럼 내 메시지는 오른쪽 남색, 상대는 왼쪽 회색** 말풍선으로 변경. (Mattermost 방식과 달라 팀장님 협의 필요로 표시)
- 🐞 변경 직후 맨 마지막 메시지에서 오류("다음 메시지"가 없음) → 바로 수정.
- lint 가 "effect 안에서 setState 금지" 규칙으로 막음 → 채널별 상태를 계산해서 쓰는 방식으로 바꿔 통과.

### 4. B-4 델타 동기화
- 팀 규칙(TECH_SPEC 2-2)대로 "마지막으로 받은 id 이후"만 `.gt("id", lastId).order("id")` 로 받아옴. 많으면 500개씩 끝까지.
- 받아오는 때: 실시간 재연결 / 탭으로 돌아옴 / 와이파이 다시 켜짐. 끊긴 동안 실패한 내 메시지는 자동 재전송.
- 와이파이를 실제로 끌 수 없어서 테스트 페이지에 **"연결 끊기 / 다시 연결" 버튼**을 달아 검증: 놓친 3개 **0.6초** 만에 채워짐, 요청은 `id=gt.26` 만 ✅
- 🐞 **휴대폰·내부 IP 주소로 열면 "확인 중…"에서 멈춤**
  → 원인: Next.js 16 개발 서버가 `localhost` 가 아닌 주소의 접속을 보안상 막음. 풀려면 `next.config.ts` 수정 필요(팀장 협의 사항이라 손대지 않음).
  → 또 Mac 와이파이를 끄면 휴대폰도 Mac 에 접속 못 하므로 이 방식 자체가 맞지 않았음 → **크롬 Offline 모드로 테스트**하기로 변경.
- 🐞 와이파이 끈 채 새로고침하면 테스트 페이지가 "확인 중…"에서 멈춤 → 서버 대신 브라우저에 저장된 로그인 정보를 읽도록 테스트 페이지 수정.

### 5. 읽음 처리 연결 (D 문수정님 요청)
- 요청: `useMarkAsRead(channelId, messages.at(-1)?.id)` 두 줄 추가.
- 검토해 보니 ① 그 파일이 아직 main 에 없어서 넣으면 build 가 깨지고 ② 내 목록엔 "보내는 중" 메시지(임시 id `-1`)가 섞여 있어 그대로 쓰면 잘못된 번호가 넘어감 → 질문으로 정리해 문수정님께 확인.
- 답변: "저장된 마지막 메시지 id 로 진행" → main 머지 후 최신 main 을 받아 연결.
- DB 로 검증: 읽음 위치 30 → 31(상대 메시지) → 32(내 메시지), `-1` 은 한 번도 안 넘어감 ✅

### 6. B-5 스레드(답글)
- **설계부터 질문으로 정함**: 답글이 있으면 "답글 3개 · 오후 3:42", 패널도 카톡식 말풍선, 채널에도 보내기는 안 함(팀 규칙 "본문은 parent_id is null 만"과 스키마 그대로).
- 오른쪽 스레드 패널 칸(layout)은 팀장 담당이라 직접 열고 닫을 수 없음 → `threads.ts` 공유 저장소를 만들어 **팀장님은 패널에 `<ThreadView />` 한 줄만** 넣으면 되게 함.
- 본문과 스레드가 같은 동작(말풍선 목록·자동 스크롤·"새 메시지 n개"·끊김 띠)을 쓰도록 `MessageRows` · `useStickToBottom` · `ChatBits` · `chatData` 로 공통 부분을 뽑아냄 → 복사 없이 재사용.
- 답글 수: 처음엔 화면의 원본 50개에 달린 답글을 id·시간만 가볍게 세고, 이후 실시간/재연결로 오는 답글도 같은 채널 구독에서 함께 셈 (같은 답글을 두 번 세지 않게 id 로 걸러냄).
- 스레드 패널은 `parent_id=eq.원본id` 로 따로 구독 + 다시 연결되면 마지막 답글 id 이후만 받아옴 (B-4 와 같은 방식).
- 답글이 없을 때 "답글 달기" 버튼을 말풍선 **아래**에 두면 B-1 때처럼 줄 간격이 벌어지므로, 마우스를 올렸을 때만 말풍선 **옆**에 나타나게 함.
- 검증: 답글 달기 → 패널에 표시, 본문엔 안 보임 ✅ / 계정2가 답글 → 패널과 본문 "답글 2개"가 새로고침 없이 갱신 ✅ / 새로고침 후에도 "답글 2개 · 오전 11:56" 유지 ✅

### 7. B-6 무한스크롤
- **설계부터 질문으로 정함**: 위로 올리면 자동으로 불러오기, 처음까지 다 불러오면 "이 채널의 첫 메시지예요 👋".
- 팀 규칙(TECH_SPEC 2-2) 그대로 `.lt("id", 가장오래된id).order("id", { ascending: false }).limit(50)`. 불러온 메시지들의 답글 수도 같이 셈.
- **스크롤 위치가 튀지 않게**: 불러오기 직전의 스크롤 높이·위치를 기억해 두고, 위에 메시지가 붙으면 늘어난 높이만큼 내려서 보던 메시지가 제자리에 있게 함.
- 메시지가 적어 스크롤이 안 생기는 채널에서도 더 불러올 수 있게, 화면이 덜 차면 바로 더 불러옴.
- 🐞 lint "선언 전에 사용" 오류 → 위치 정리를 스크롤 도우미(`useStickToBottom`) 안에서 하도록 옮겨 해결.
- **테스트 데이터**: #general 은 35개뿐이라 테스트 불가 → 팀원 화면에 안 보이게 **비공개 채널 `gyeseop-test`**(계섭테스트1·2만)를 만들어 메시지 120개 넣고 확인.
- 검증: 처음 50개(71~120) → 맨 위로 올리면 100개(21~120) → 120개(1~120) + "첫 메시지예요" ✅ / 보던 메시지 위치 불러오기 전후 108px → 108px 그대로 ✅ / 중복 없음 ✅
- 덤으로 채널이 2개가 되어 미뤄둔 확인도 함: **#general 을 보는 동안 다른 채널에 온 메시지가 섞여 들어오지 않음** (채널 바꾸면 이전 구독 해제) ✅

### 9. 첨부 칸 열기 (팀장님 CONTRACTS.md · 문수정님 요청)
- 팀장님이 만든 연결 규격 문서(`DevelopDoc/CONTRACTS.md`)에 "B 가 열어 줄 칸"으로 적힌 것을 **규격 그대로** 만듦 → 문수정님이 첨부 기능을 붙일 때 내 파일을 고칠 필요가 없음.
  - `MessageList` / `MessageItem`: `renderAttachments?(message)` — 말풍선 **바로 아래**에 첨부를 그릴 칸
  - `MessageInput`: `extras?: ReactNode` — 입력창 **아래**에 첨부 버튼·@멘션을 놓을 칸

- **보내는 중·실패 메시지에는 첨부 칸을 그리지 않음** — 아직 DB id 가 없어서(임시 id -1) 첨부를 연결할 수 없기 때문.

### 12. @멘션 자동완성 연결 + 스레드 Esc 충돌 방지 (팀장님 후속 요청, PR #24 머지 후)
- 팀장님 요청 2가지를 받아 **최신 main 에서 새 브랜치** `feature/gyeseop-mention-hook` 로 작업 (팀 규칙대로).

  - 훅은 입력창(textarea)에 **직접** 키 리스너를 붙임 → 문서 전체에 붙은 내 스레드 리스너보다 **먼저** 실행됨

  - **Esc**: `preventDefault` 만 → 내 스레드 리스너에서 `e.defaultPrevented` 로 "목록이 이미 처리함"을 알 수 있음 → 팀장님 추천 **방법 A** 가 맞음
- 요청 1 (`MessageInput.tsx`): import 1줄 + `useMentionAutocomplete({ channelId, textareaRef: ref, text, setText })` + 입력창 줄 바로 위 `{mention.popup}` — 스레드 답글 입력창에도 자동 적용.
- 요청 2 (`ThreadView.tsx`): Esc 리스너에 `if (e.defaultPrevented) return;` 추가.
- 검증 (최신 main 첫 화면, 계섭테스트1):
  - 본문 입력창 `@` → 이름 목록 ✅ / ↓ 이동 ✅ / Enter → "@테스트1 " 들어가고 **전송 안 됨** ✅ / Esc → 목록 닫힘 ✅
  - 스레드 입력창 `@` → 목록 ✅ / **첫 Esc → 목록만 닫히고 스레드 유지** ✅ / 두 번째 Esc → 스레드 닫힘 ✅
  - (함께 받은 확인 항목) **답글 전송 시 DB 에 parent_id 저장, 채널 본문에는 안 나옴**: 답글 1개 보내서 DB 확인 `parent_id = 1`(원본 "테스트 메시지입니다 👋") ✅, 본문엔 없고 원본에 "답글 1개" ✅ → 확인 후 테스트 답글 삭제
