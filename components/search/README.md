# components/search — E UI·검색·AI

## E-2 키워드 검색

- `MessageSearch.tsx`: 검색창·결과 목록. Enter 또는 검색 버튼으로 조회합니다.
- `searchMessages.ts`: 로그인 확인 후 `messages.content`에 `ilike` 포함 검색을 수행합니다. 외부 AI API 키는 필요하지 않습니다. 소프트 삭제된 메시지(`deleted_at`이 있는 행)는 `.is("deleted_at", null)` 조건으로 제외합니다.
- `searchMessages.test.mjs`: 실제 DB 대신 테스트용 응답으로 조회 조건·오류·취소 처리를 확인합니다.

### 연결 계약 — 팀장 협의 후 적용

`MessageSearch`를 사용하는 **클라이언트 컴포넌트**에서 아래 형태로 연결합니다. 일반 함수를 서버 컴포넌트에서 props로 직접 넘기지 않습니다.

```tsx
import MessageSearch from "@/components/search/MessageSearch";

// 기존 채널·메시지 선택 상태를 관리하는 클라이언트 컴포넌트 안에서:
<MessageSearch
  onSelect={(channelId, messageId) => {
    // C·B·팀장과 정한 방식으로 채널을 선택하고 해당 메시지로 이동합니다.
    // channelId: string, messageId: number
  }}
/>
```

결과 버튼은 `onSelect(channelId, messageId)`를 호출합니다. 이 컴포넌트가 직접 라우팅하거나 채널 상태를 만들지는 않습니다. 스레드 답글을 선택한 경우에는 B 담당과 원본·답글 표시 방법을 협의해야 합니다.

**`components/layout/MessageArea.tsx`는 변경하지 않았습니다.** 헤더 검색 자리 연결과 실제 채널·메시지 이동은 A·B·C 협의 및 화면 연동 검증이 남아 있습니다. 연결 전에는 `npm run dev`를 실행해도 기존 화면에 검색창이 추가되지 않습니다.

### 검색 동작과 제한

- 빈 검색어는 조회하지 않으며, 앞뒤 공백을 제거합니다. 검색어는 최대 100자입니다.
- 로그인 사용자의 Supabase 클라이언트를 사용합니다. 조회 가능한 메시지 범위는 DB의 `messages_select` RLS(행 단위 접근 권한)가 제한합니다. 관리자 키를 사용하지 않습니다.
- `%`, `_`, 역슬래시는 문자로 검색하도록 이스케이프합니다.
- `created_at` 내림차순, 동일 시각에는 `id` 내림차순입니다. 원본 메시지와 스레드 답글 모두 검색합니다.
- 최대 50건을 표시합니다. 추가 결과가 있으면 검색어를 구체화하라는 안내를 표시합니다. 전체 결과 수나 페이지 이동은 제공하지 않습니다.
- 입력 변경·결과 닫기·컴포넌트 해제 시 요청을 취소하고, 이전 응답이 새 결과를 덮어쓰지 않게 합니다. 로그인·로그아웃 시에도 이전 결과를 지웁니다.
- 초기에는 검색창만 표시합니다. 조회 중·결과 없음·로그인 필요·연결 설정 누락·조회 실패 상태를 안내합니다.
- 결과는 Tab으로 이동하고 Enter/Space로 선택합니다. Escape·닫기 버튼·바깥 클릭으로 목록을 닫습니다. 메시지는 HTML로 삽입하지 않고 일반 텍스트로 표시합니다.

### 자동 검사

프로젝트 루트에서 Node 24로 실행합니다. 패키지 설치나 실제 계정은 필요하지 않습니다.

```bash
node --test components/search/searchMessages.test.mjs
npm run lint
npm run build
```

테스트용 응답으로 진행하는 검사는 실제 DB의 RLS, 실제 검색 결과, 브라우저에서의 클릭·채널 이동을 증명하지 않습니다.

### 화면 연동 후 확인할 항목

- [ ] 두 계정으로 각자 접근 가능한 채널·DM만 검색되는지 확인

- [ ] 대소문자·한글·검색 결과 없음·특수문자 검색 확인
- [ ] 결과가 최신순이며 50건 초과 안내가 나오는지 확인
- [ ] 결과 클릭으로 정확한 채널·메시지 ID가 전달되고 실제 이동하는지 확인
- [ ] 빠른 입력 변경·닫기·로그아웃 후 이전 결과가 표시되지 않는지 확인
- [ ] 한글 조합 중 Enter가 조기 검색을 일으키지 않는지 확인

## E-3 요약 UI — EXAONE 서버 연결

- `AiToolsBar.tsx`: `channelId: string | null`을 받는 요약 버튼·범위 선택(최근 10/25/50개)·로딩·취소·안내·결과 표시 컴포넌트입니다.
- `summaryClient.ts`: 로그인 쿠키와 함께 내부 `/api/ai/summarize`에 `{ channelId, limit }`을 전달합니다. 대화 원문·외부 AI 키를 브라우저에서 전달하지 않습니다.
- `summaryClient.test.mjs`: 테스트용 HTTP 응답으로 클라이언트 요청·오류·취소를 검사합니다.
- 요약·AI 검색·할 일 추출 응답 대기는 모두 최대 240초(4분)이며 로딩 중 취소할 수 있습니다. `AI_TIMEOUT`(앱/업체 응답 제한)과 요약의 `SERVER_TIMEOUT`(표준 앱 오류 JSON이 없는 HTTP 504)을 구분해 안내합니다. HTTP 504만으로 배포 플랫폼이 원인이라고 확정하지는 않습니다. 요청/응답 계약과 자동 재시도 없음은 유지합니다.
- `aiRequestGate.ts`와 `AiRequestProgress.tsx`: 한 채널의 요약·검색·추출을 공유 잠금으로 하나만 실행합니다. 진행 종류·분:초 경과 시간·취소를 표시하며, 패널을 닫아도 버튼 옆에 실행 상태가 남습니다. 닫기는 취소가 아닙니다. 채널 변경/화면 해제는 진행 요청을 중단하고 결과를 초기화합니다. 다른 탭/사용자/서버 전체 호출량을 제한하는 기능은 아닙니다.

```tsx
import AiToolsBar from "@/components/search/AiToolsBar";

<AiToolsBar channelId={channelId} />
```

요약을 요청하면 서버가 로그인·채널 권한을 확인하고 EXAONE을 호출합니다. 서버 전용 `EXAONE_API_KEY`가 없으면 설정 안내를 표시합니다. 선택 범위 대화가 외부 EXAONE에 전송되므로 허용된 대화에만 사용하세요. 키는 브라우저에서 읽거나 전달하지 않습니다. 채널 변경 시 이전 결과를 초기화하고 요청을 취소합니다. 일반 자동 테스트에서는 실제 AI를 호출하지 않습니다.

팀 연결 규격에 따라 **팀장이 `components/layout/slots.tsx`의 `AiToolsSlot`에서 연결**해야 화면에 나타납니다. 해당 레이아웃 파일은 변경하지 않았습니다. API 동작·검사·제한은 [AI API 안내](../../app/api/ai/README.md)를 참고하세요.

- [ ] 실제 브라우저에서 채널 변경·취소·설정 누락·권한·한도 오류 안내 확인
- [ ] 두 계정으로 채널 접근 권한 확인
- [ ] 인증된 API와 연결된 실제 화면에서 요약 내용·품질·속도 검증 (업체 단독 테스트와 구분)

## E-4 자연어 검색·할 일 추출 UI

- `AiExtraTools.tsx`: 기존 `AiToolsBar(channelId)` 안에 포함됩니다. props 계약은 유지되며 공용 슬롯은 변경하지 않았습니다.
- 현재 채널의 자연어 검색(질문 최대 500자·결과 최대 20건), 할 일 추출(최근 5/10/25개·기본 10개, 응답이 잘리면 "더 작은 범위로 줄여 다시 시도" 버튼 — 자동 재시도 없음), 로딩·취소·빈 결과·설정/권한/한도/시간 오류와 결과를 표시합니다.
- 검색은 해석한 키워드·기간을 서울 시간으로 보여 줍니다. 실제 결과는 서버가 RLS로 조회한 DB 메시지입니다. AI가 검색 결과 메시지를 만들어 내지 않습니다.
- 추출 결과는 내용·담당자/기한 미정·근거 메시지 ID와 원문 확인 안내를 표시합니다. 업무 저장·자동 배정·특정 과거 메시지 위치 이동은 하지 않습니다.
- `extraClient.ts`는 동일 출처 쿠키로 내부 API만 호출하고 성공 응답 형식을 검사합니다. 채널/범위 변경·취소·로그아웃/로그인 시 이전 요청/결과를 지우고 늦게 도착한 응답은 표시하지 않습니다.
- E-3 요약과 E-4 검색/추출은 같은 `AiToolsBar` 안에서 진행 중 동시 실행을 막습니다. `AiExtraTools`의 선택 props `requestGate`를 통해 공유하며, 단독 사용 시에는 자체 잠금을 사용합니다. 서버 전체 호출량 제한이나 다른 탭의 동시 실행까지 막는 것은 아닙니다. 실제 대화 외부 전송·사용량 정책은 별도 협의해야 합니다.
- `extraClient.test.mjs`는 가짜 HTTP로 요청/오류/형식/취소를 검사합니다. 독립 브라우저의 고정 샘플 검사는 실제 AI/로그인/DB/슬롯 검증과 구분합니다.
- **실제 검색 조건 해석은 합성 질문 1회 성공. 할 일 추출은 25초·45초에서 실패했으나 원인 조사 후 대기 제한을 240초로 늘려 같은 합성 대화 1회가 37,974ms에 성공**(명시 기한·담당자·상대 기한·미정 처리·인사 제외 검사 통과)했습니다. 배포 함수에는 `maxDuration = 300`을 명시했고 UI에도 최대 4분 정도 걸릴 수 있음을 안내합니다. 실제 앱 로그인·실DB·배포·사내 대화 품질은 여전히 미검증입니다.
- API 정책·대기 제한·남은 검증: [E-4 API 안내](../../app/api/ai/E4.md)
- PR 전 확인한 원격 main `fed9b4c`에는 `AiToolsSlot`의 `AiToolsBar` 연결 코드가 있습니다. 이 변경 병합 시 E-4 UI가 함께 노출될 수 있으므로, 실제 추출 지연 미해결 상태의 활성화 여부를 팀장이 검토해야 합니다. 이 브랜치는 공용 슬롯을 수정하지 않았으며 인증된 통합/배포 동작은 미검증입니다.

## 관리자 AI 연결 테스트의 대기 안내

`AiKeyStatus.tsx`는 확인창 승인 후에만 호출하며, 연결 테스트도 최대 240초입니다. 공통 진행 표시를 재사용해 경과 시간과 취소 버튼을 제공합니다. 취소/해제 후 늦게 도착한 응답은 표시하지 않습니다. 관리자 페이지의 잠금은 채팅 도구와 별개 화면의 잠금입니다. 이미 업체가 처리한 사용량을 취소로 되돌릴 수는 없습니다.

## 탭 이동 중에도 AI 요청 유지 (로그아웃할 때만 취소)

Supabase는 다른 탭에 갔다가 돌아오면 로그인 상태를 다시 확인하며 **같은 계정의 `SIGNED_IN`** 신호를 다시 보냅니다(`@supabase/auth-js` 2.119.1의 `_recoverAndRefresh`). 이전에는 `AiExtraTools`가 이 신호로 요청을 취소해서, 탭만 바꿔도 AI 검색·할 일 추출이 끊길 수 있었습니다.

이제 요약·AI 검색·할 일 추출과 상단 키워드 검색(`MessageSearch`, 열린 결과 목록)은 `useCancelOnSignOut` 하나로 같은 규칙(`authCancel.ts`)을 씁니다.

| 로그인 신호 | 처리 |
|---|---|
| `SIGNED_OUT` (로그아웃) | 실행 중인 요청을 취소하고 이전 결과를 지운다 |
| `SIGNED_IN` + 다른 계정 | 이전 계정이 로그아웃된 것으로 보고 취소한다 |
| `SIGNED_IN` + 같은 계정 (탭 복귀) | 유지한다 |
| `TOKEN_REFRESHED`·`USER_UPDATED`·`INITIAL_SESSION` | 유지한다 |

```bash
node --test components/search/authCancel.test.mjs
```

## AI 제공업체 표시 (EXAONE / Gemini)

서버 환경변수 `AI_PROVIDER`로 업체를 고르므로(자세한 내용은 `app/api/ai/README.md`의 "AI 제공업체 선택") 화면의 안내문은 업체 이름을 하드코딩하지 않는다.

- `useAiProviderLabel`(훅)이 `GET /api/ai/status?view=public`에서 업체 **이름만** 한 번 받아 `AiToolsBar`·`AiExtraTools`의 안내문("선택한 범위의 대화가 외부 AI 서비스(Gemini)로 전송됩니다")에 넣는다. 받기 전이나 실패 시에는 "외부 AI 서비스"로 보이며, 키 관련 정보는 받지 않는다.
- 관리자 `AiKeyStatus`는 키가 없을 때 넣어야 할 환경변수 **이름**(`EXAONE_API_KEY`/`GEMINI_API_KEY`)과 `AI_PROVIDER` 사용법을 보여 주고, 연결 테스트 확인창에 실제 업체 이름을 쓴다.
- `aiStatusClient.ts`: `fetchAiProviderInfo`(이름만), `aiTargetText`(문구), `fetchAiStatus`가 `providerId`·`keyEnvName`을 선택적으로 받는다(이전 응답 모양과 호환).
