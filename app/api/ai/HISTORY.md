## 요약 API 첫 검증 (2026-11-23, EXAONE)

- 짧은 합성 대화 4개로 연결 함수에서 실제 EXAONE 1회 호출: HTTP 200, 약 10.7초, 최종 요약 수신. 해당 예제의 일정·담당자·미정 사항을 원문과 대조했습니다. 일반적인 요약 품질·긴 대화 성능까지 검증한 것은 아닙니다.
- 단위 테스트와 비로그인 실제 HTTP 검사는 별도 수행했습니다. 로그인한 실제 API의 성공 응답·두 계정 DB 권한·브라우저 UI·Vercel 반영은 아직 검증하지 않았습니다.
- 최소 범위 10개 요약 시간 초과 제보를 조사했습니다. 같은 합성 대화 10개의 실제 업체 검사 2회는 이전 25초 설정에서 10,923ms, 중간 제안 120초 설정에서 12,544ms로 모두 성공했습니다. **실제 사용자 실패를 재현하거나 수정 전후 속도 개선을 증명한 결과가 아닙니다.** 이후 사용자 요청으로 모두 240초로 통일했으며 추가 실제 AI 호출 없이 지연 HTTP 자동 검사로 이전 25초 제한의 실패와 새 제한의 성공을 확인했습니다. 배포본은 별도 재확인이 필요합니다. ## 요약 응답 한도 실측과 상향 (2026-11-24)

요약도 EXAONE이 생각 토큰까지 `max_tokens`에 포함해서 쓰므로, 할 일 추출에서 응답 잘림이 확인되어 같은 위험을 점검했다.

- **방법:** 지어낸 업무 대화 50개(본문 2,112자, 실제 사내 대화·실명 아님)로 실제 EXAONE을 3회 호출했다. 요약 기능의 실제 프롬프트를 쓰고, 이 측정에서만 요청의 `max_tokens`를 6,144로 풀어 "실제 필요량"을 쟀다(응답 원문 미기록, 토큰 수·시간만 기록).
- **결과:**

| 회차 | 생각 | 전체 생성 | 시간 | 이전 한도 2,048 대비 |
|---|---|---|---|---|
| 1 | 1,455 | 1,678 | 58초 | 82% |
| 2 | 947 | 1,169 | 45초 | 57% |
| 3 | 849 | 1,070 | 41초 | 52% |

- **해석:** 이 입력에서는 3회 모두 2,048 안에서 끝났다(잘림 없음). 다만 필요량이 1.6배 변동하고 최대가 한도의 82%라 여유가 작다. 실제 대화는 더 길고 복잡할 수 있다.
- **조치:** `SUMMARY_MAX_TOKENS` 2,048 → **4,096**. 쓰지 않으면 비용이 없고, 다 써도 최저 속도(약 26토큰/초)로 약 158초라 240초 제한 안이다. 잘림 안내문은 "대화 범위를 줄여"가 원인과 맞지 않아 "다시 시도해 주세요. 반복되면 대화 범위를 줄여 보세요."로 바꿨다.
- **한계:** 표본 3회, 입력은 짧은 한 줄 메시지 50개라 긴 메시지 위주의 실제 대화와 다를 수 있다. 4,096에서의 동작은 실제 호출로 다시 확인하지 않았다(필요량 측정은 6,144로 했다). 화면의 "다시 시도" 버튼은 버튼 정리(#82) 병합 후 추가한다.

## 요약에 말한 사람 표시 (2026-11-24)

**변경:** 채널 요약이 메시지 본문만 보내던 것을 **`[이름] 본문` 형식으로 말한 사람을 붙여** 보낸다. 요약의 결정·후속 작업에 "누가" 하기로 했는지가 들어간다. 이름은 **실명 그대로** 전송한다(사용자 결정: 익명 라벨 복원 방식 대신 실명).

- **조회:** `messages.user_id → profiles.name`을 `profiles!messages_user_id_fkey(name)`로 함께 읽는다(연결이 2개라 외래키 이름이 필요 — `components/chat/types.ts` 참고). 새 DB 변경·권한 변경 없음(`profiles`는 로그인한 사용자가 모두 읽을 수 있고, 요약은 이미 채널 멤버만 호출할 수 있다).
- **형식:** `formatSpeakerLine` — 이름이 없으면 `[알 수 없음]`, 이름 안의 줄바꿈·대괄호는 공백으로 바꾸고 30자로 제한(형식·프롬프트 흉내 방지).
- **길이 제한:** 원문 4,000자·합계 20,000자는 **원문 기준**으로 먼저 검사하고, 이름 접두어(최대 64자)는 어댑터에서 별도 여유로 둔다. 직접 텍스트 입력(`messages`)은 이전처럼 4,000자 엄격 검사.
- **프롬프트:** "각 메시지는 `[이름] 본문` 형식이며 이름은 말한 사람", "결정·후속 작업에는 말한 사람의 이름을 함께", "제가·내가 하겠다는 말은 그 말을 한 사람이 담당자". 기존 "원문에 없는 사실·담당자·기한을 만들지 마세요"는 유지.
- **화면 안내:** "선택한 범위의 대화**와 작성자 이름**이 외부 EXAONE으로 전송됩니다."로 바꿨다. 이전에는 작성자 이름을 보내지 않았으므로 사용자에게 알려야 한다. 본문에 이미 적힌 이름은 이전에도 그대로 전송됐다.
- **스레드 답글**은 이전처럼 요약 대상이 아니다(`parent_id is null`).

**실제 호출 측정(지어낸 대화 50개, 지어낸 이름 4명이 번갈아 발화, 서비스 한도 4,096, 3회):**

| 회차 | 프롬프트 | 생각 | 전체 생성 | 시간 | 4,096 대비 |
|---|---|---|---|---|---|
| 1 | 1,239 | 2,048 | 2,313 | 70초 | 56% |
| 2 | 1,239 | 1,513 | 1,798 | 63초 | 44% |
| 3 | 1,239 | 1,817 | 1,999 | 67초 | 49% |

- 이름이 붙으면 AI가 화자를 구분하느라 **생각이 늘었다**(이름 없을 때 전체 1,070~1,678 → 1,798~2,313, 약 +40%). 기존 한도 2,048이었다면 3회 중 2회가 잘렸을 양이라 **한도 4,096(#83)이 필요**하다. 최악 시간은 4,096토큰 ÷ 26토큰/초 ≈ 158초로 제한 240초 안.
- **정확도 확인:** 요약문의 "누가 무엇을" 주장 약 14건(담당·제안·참석·링크 공유 등)을 입력 대화의 실제 화자와 대조했고 모두 일치했다. 표본이 작아 오귀속이 없다는 보장은 아니며, 화면은 "AI 결과는 틀릴 수 있습니다. 원문 대화를 함께 확인해 주세요."를 안내한다.
- **한계:** 표본 3회, 입력은 지어낸 짧은 한 줄 메시지 50개. 실제 대화(긴 메시지·여러 주제·같은 이름의 다른 사람)에서의 정확도와 생각 길이는 다를 수 있다. 같은 이름의 사람이 둘이면 AI가 구분하지 못할 수 있다.
