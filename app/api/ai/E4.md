# E-4 자연어 검색·할 일 추출 — EXAONE 연결

> 실제 route에 서버 전용 `EXAONE_API_KEY`로 EXAONE을 연결했습니다. **합성 질문의 실제 검색 조건 해석 1회와, 대기 제한을 240초로 늘린 뒤 합성 대화 3개의 할 일 추출 1회가 모두 성공했습니다**(추출 37,974ms·HTTP 200·검사 5개 통과). 인증된 API·실DB 권한·앱 슬롯·배포 검증과는 별개입니다.

E-3와 같은 서버 Supabase 클라이언트·로그인·RLS·오류 응답 방식을 사용합니다. 새 패키지·환경변수 파일·DB/권한/공용 설정은 변경하지 않았습니다. 질문 또는 조회 대화가 외부 EXAONE에 전송되므로 허용된 데이터에만 사용해야 합니다. 모듈 불러오기·자동 테스트·빌드만으로 실제 AI를 호출하지 않습니다.

## 1. 자연어 검색 — `POST /api/ai/search`

요청:

```json
{ "query": "지난주 배포 얘기", "channelId": "11111111-1111-4111-8111-111111111111", "limit": 20 }
```

- `query`: 공백 제거 후 1~500자.
- `channelId`: 선택. 있으면 해당 채널의 멤버 여부를 서버에서 확인합니다. 없으면 로그인 사용자의 기존 메시지 RLS 범위 안에서 검색합니다.
- `limit`: 선택. 기본 20, 최대 50. 정수만 허용합니다.
- 정한 필드 외의 입력·잘못된 UUID·빈 질문은 거절합니다.

### 처리 경계

1. 서버가 로그인·선택 채널 권한을 확인합니다.
2. AI 연결 함수에 질문과 서버 기준 시각 `referenceTime`, `timeZone: Asia/Seoul`을 전달합니다.
3. 연결 함수의 `{ keywords, from, to }`를 검증합니다. 키워드 최대 5개·각 100자, 시간대가 있는 ISO 시각과 올바른 날짜·기간만 허용합니다.
4. 서버가 검증된 키워드를 `content ilike` AND 조건으로, 시각은 `created_at >= from`·`created_at < to`로 변환합니다. 키워드가 없으면 시작·종료 시각이 모두 필요합니다.
5. RLS가 적용된 DB에서 실제 메시지를 조회합니다. 모델이 메시지 본문을 만들어 결과로 돌려주게 하지 않습니다.

AI 출력에 SQL·channelId·limit 등 계약 밖 필드가 있으면 거절합니다. 사용자 채널과 조회 개수는 AI가 바꿀 수 없습니다. `%`, `_`, 역슬래시는 문자로 이스케이프하며, PostgREST의 와일드카드 별칭 `*`가 들어간 AI 키워드는 거절합니다.

결과는 원본·답글 모두 포함하며 `created_at`, `id` 최신순입니다. 최대 limit건과 추가 결과 여부를 반환합니다. 임베딩 기반 의미 순위 검색이 아니라 AI가 해석한 조건을 이용하는 DB 필터 검색입니다. 표현이 다른 동의어까지 모두 찾는 것을 보장하지 않습니다.

성공 응답 계약:

```text
{
  messages: [{ id, channel_id, content, created_at, parent_id }, ...],
  hasMore: boolean,
  interpretation: { keywords: string[], from: ISO시각 | null, to: ISO시각 | null },
  referenceTime: ISO시각,
  timeZone: "Asia/Seoul"
}
```

상대 날짜는 서버 기준 시각의 **서울 시간**을 사용합니다. 오늘/어제는 현지 자정 기준, 이번 주/지난주는 **월요일 00:00~다음 월요일 00:00(끝 제외)**입니다. 서버가 계산한 기준 범위도 모델에 제공합니다. 이는 이번 구현의 정책이며 팀 공용 계약 확정은 협의 대상입니다. 조건을 만들 수 없거나 출력이 잘못되면 검색을 실행하지 않고 오류로 안내하며, 질문 전체를 단순 키워드 검색으로 대체하지 않습니다.

## 2. 할 일 추출 — `POST /api/ai/tasks`

요청:

```json
{ "channelId": "11111111-1111-4111-8111-111111111111", "limit": 50 }
```

- `channelId`는 필수, `limit`은 선택이며 기본 50·최대 100입니다.
- 서버가 로그인·채널 멤버 여부를 확인하고, RLS를 적용해 해당 채널의 최근 메시지를 조회합니다. **원본과 답글을 모두 포함**합니다.
- 빈 본문은 제외하고 시간순으로 정리하여, 메시지 ID·본문·작성 시각·답글 원본 ID를 추출 연결 함수에 전달합니다.
- 본문당 4,000자·전체 20,000자 제한이 있습니다. 넘으면 메시지 개수를 줄이도록 안내하고 임의로 잘라 완료 처리하지 않습니다.

성공 응답 형식 예시 — 실제 추출 결과가 아닙니다:

```json
{
  "tasks": [
    { "content": "테스트 할 일", "assignee": null, "dueDate": null, "messageIds": [10] }
  ],
  "messageCount": 2
}
```

- `content`: 내용, 1~1,000자.
- `assignee`: 근거 메시지에 실제로 등장하는 이름 텍스트 또는 `null`. 계정 UUID로 자동 배정하지 않습니다.
- `dueDate`: 실제 달력에 존재하는 `YYYY-MM-DD` 또는 `null`. 불명확하면 추측하지 않습니다.
- `messageIds`: 이번 조회에 포함된 근거 메시지 ID 1~10개. 다른 채널·조회 범위 밖의 ID는 거절합니다.
- 최대 20개 할 일을 허용합니다. AI가 할 일이 없다고 판단한 경우에만 빈 배열을 사용할 수 있으며, 기본 미연결 상태는 빈 배열 성공을 반환하지 않습니다.
- 할 일을 DB에 저장하거나 담당자·기한을 실제 업무로 확정하는 API는 아닙니다.

AI가 반환한 이름이 인용 원문에 있는지, 기한 형식·달력·메시지 ID가 유효한지를 검사합니다. **이 검사만으로 내용의 의미나 담당자 배정·기한 추론의 정확성이 보장되지는 않습니다.** 상대 기한은 실행 시각이 아니라 해당 근거 메시지의 작성 시각(서울 날짜)을 기준으로 해석하도록 요청합니다. 원문에 명시된 날짜를 우선하고 불명확한 이름/날짜는 null로 요청합니다. 실제 추출 호출이 시간 초과돼 이 의미·날짜 처리의 실제 품질은 아직 미검증입니다.

## 3. 오류와 보안

E-3와 같은 `{ error: { code, message } }` 형식과 `Cache-Control: no-store`를 사용합니다. 메시지 원문·키·내부 DB/AI 오류를 오류 응답이나 로그에 남기지 않습니다. AI 연결 함수는 서버 코드에만 둡니다.

| HTTP | 코드 예 | 의미 |
|---|---|---|
| 400 | `INVALID_JSON`, `INVALID_INPUT`, `INVALID_QUERY`, `INVALID_CHANNEL`, `INVALID_LIMIT` | 입력 오류 |
| 401 | `UNAUTHORIZED` | 로그인 필요·인증 확인 실패 |
| 403 | `FORBIDDEN` | 채널 비회원. 채널 존재 여부를 구분하여 노출하지 않음 |
| 408 | `REQUEST_ABORTED` | 요청 취소 |
| 413 | `INPUT_TOO_LARGE` | 본문 최대 128KiB 또는 대화 길이 제한 초과 |
| 415 | `JSON_REQUIRED` | JSON Content-Type 필요 |
| 422 | `NO_MESSAGES` | 할 일 추출 대상 대화 없음 |
| 429 | `AI_RATE_LIMITED` | 업체 호출 한도 제한 |
| 500 | `DATABASE_ERROR`, `INTERNAL_ERROR` | 일반화한 내부 오류 |
| 502 | `INVALID_AI_RESPONSE`, `AI_OUTPUT_TRUNCATED` | 잘못된 형식/근거·잘린 응답 |
| 502 | `AI_AUTH_FAILED`, `AI_SERVICE_ERROR`, `AI_CONNECTION_FAILED` | 업체 키/모델 권한·서비스·연결 오류 |
| 503 | `AI_NOT_CONFIGURED`, `SERVICE_NOT_CONFIGURED` | 서버 AI 키·Supabase 설정 누락 |
| 504 | `AI_TIMEOUT` | 업체 요청/본문 대기 제한 초과 |

공통 처리는 E-4 전용 `extra.ts`에 있으며 실제 route만 `createExaoneExtra`에 서버 키를 전달합니다. 독립 handler의 기본값은 테스트 안전성을 위해 외부 호출 없는 `AI_NOT_CONNECTED`입니다. 테스트 성공을 실제 AI 성공으로 소개하지 않습니다.

- 고정 주소 `https://api.exaone.ai/v1/chat/completions`, 모델 `k-exaone_v2.5`, 비스트리밍·low 추론·최대 4,096 토큰(추론 포함). 외부 키·모델·주소를 사용자 입력으로 변경할 수 없습니다.
- `stream: false`이므로 업체가 생성을 끝내야 응답 헤더/상태가 도착합니다. 대기 제한 전에 끝나지 않으면 상태 코드 없이 `AI_TIMEOUT`이 됩니다. 이는 25초·45초 실패와 일치하는 현상입니다.
- 대기 제한은 사용자 요청으로 **검색·추출 모두 240초**로 통일했습니다(요약도 동일). 추출은 25초·45초에서 실패해 2026-11-23에 240초로 늘렸고, **같은 합성 입력의 실제 호출이 37,974ms에 성공했습니다.** 4,096토큰을 모두 생성하는 시간의 참고 추정(공개 측정 약 20토큰/초 기준 약 205초)을 감안해 배포 함수 한도 300초보다 짧게 두었습니다. 실제 생성 시간의 상한을 보장하는 것은 아닙니다.
- `app/api/ai/search/route.ts`, `tasks/route.ts`에 `maxDuration = 300`을 명시했습니다. 이는 Fluid compute 기준 Vercel Hobby의 기본값이자 최대값이며, 로컬 `npm run dev`에는 적용되지 않습니다. 배포 플랜·Fluid compute 설정에 따라 실제 한도가 달라질 수 있어 팀장 확인이 필요합니다.
- 최종 `message.content`의 JSON만 사용합니다. 추론 필드·설명·코드 블록·업체 오류 원문은 반환하지 않습니다. 계약 밖 필드/빈 조건/잘린 출력은 거절하며 실제 AI로 가장한 고정 결과는 없습니다.
- 자동 재시도·리다이렉트·다른 업체/유료 전환 없음. 취소 신호를 전달하나 이미 처리된 업체 사용량까지 취소되는 것은 아닙니다. 서버 전체 사용자 호출량 제한은 아직 없으므로 배포 전 사용량 관리 협의가 필요합니다.
- 데이터 안의 지시를 따르지 않도록 요청하지만 프롬프트 지시 공격 방어·품질을 보장하지 않습니다. [공식 모델 문서](https://docs.exaone.ai/ko/docs/k-exaone-2.5)

## 4. 검사

프로젝트 루트에서 Node 24로 실행합니다. 외부 AI 키·추가 설치는 필요하지 않습니다.

```bash
node --test app/api/ai/extra.test.mjs app/api/ai/exaone-extra.test.mjs components/search/extraClient.test.mjs components/search/searchKeyboard.test.mjs
npm run lint
npm run build
node app/api/ai/extra-smoke.mjs
```

마지막 명령은 기존 Supabase 환경변수가 있는 로컬에서 빌드된 실제 Next.js를 임시 포트로 열어 입력 오류·비로그인·POST 전용 HTTP 10개를 검사하고 종료합니다. 로그인 쿠키·실제 대화·외부 AI는 사용하지 않습니다. 로그인 후 권한이나 AI 검색·추출 품질의 증빙은 아닙니다.

직접 호출하려면 `npm run dev` 실행 후 PowerShell에서 예를 들어:

```powershell
$body = @{ query = "Test deployment question" } | ConvertTo-Json -Compress
Invoke-WebRequest -Uri http://localhost:3000/api/ai/search -Method Post -ContentType application/json -Body $body
```

쿠키 없는 정상 요청은 401이며 PowerShell이 예외로 표시할 수 있습니다. 인증된 정상 요청에서 서버 키가 있으면 실제 EXAONE을 호출하고, 키가 없으면 `AI_NOT_CONFIGURED`입니다. 키·쿠키를 코드나 채팅에 올리지 마세요.

### 추출 지연 원인 조사 (2026-11-23)

확인된 사실과 아직 확인하지 못한 것을 구분합니다. 원인 조사만으로는 외부 AI를 호출하지 않았습니다.

| 근거 | 내용 | 해석 |
|---|---|---|
| 실행 기록 | 검색 해석은 13,109ms에 200, 추출은 25,011ms·45,011ms 모두 상태 코드 없이 중단 | 같은 키·모델에서도 요청 종류에 따라 걸리는 시간이 크게 다름 |
| 코드 | `stream: false`, `max_tokens: 4096`(추론 포함), `reasoning_effort: "low"` | 생성이 끝나야 응답이 오고, 추론 토큰도 4,096 한도에 포함 |
| [EXAONE 모델 문서](https://docs.exaone.ai/ko/docs/k-exaone-2.5) | 최대 컨텍스트 524,288, `max_tokens`는 추론 포함. 추론 강도 low/high/max(기본 max) | 모델 파라미터로 생성량 상한을 조절할 수 있음 |
| 공개 측정(2026-11-11, 외부 벤치마크) | 같은 모델 출력 속도 약 20토큰/초 | 4,096토큰이면 생성만 약 205초. **공식 수치가 아닌 참고값** |
| [Vercel 함수 한도](https://vercel.com/docs/functions/limitations) | Fluid compute 기준 Hobby 기본·최대 300초, Pro 최대 800초 | 5분은 Hobby에서 가능한 상한. 그 이상은 플랜·설정 확인 필요 |

- **가장 유력한 가설:** 무료 API의 느린 생성 속도 때문에 추출 응답이 45초 안에 완성되지 못했다는 것입니다. 검색(짧은 JSON)은 13초에 끝났고, 추출은 더 긴 출력·추론이 필요합니다.
- **조사 후 실제 확인:** 240초 제한으로 같은 합성 대화 3개를 추출한 결과 **HTTP 200·37,974ms·검사 5개 모두 통과**했습니다(명시 기한·명시 담당자·상대 기한·담당자 미정·인사 제외). 45초 실패와 38초 성공이 함께 나타난 것은 **생성 시간이 45초 부근에서 흔들린다**는 뜻이며, 240초는 그 변동을 덮는 여유입니다. 실제 사내 대화·품질 일반화는 여전히 미검증입니다.
- **아직 확인하지 못한 것:** 업체 대기열·모델 추론·네트워크 중 어느 구간이 느린지, 240초면 실제로 성공하는지, 실제 추출 내용·품질입니다. 키 오류·한도 초과·모델 권한 문제라는 근거는 없습니다(그 경우 401/403/429 상태가 왔을 가능성이 큼).
- **5분으로 늘릴 때의 제약:** 클라이언트 대기 240초 + DB·응답 시간이 배포 함수 한도 300초 안에 들어와야 합니다. Hobby는 300초가 최대라 여유가 크지 않고, 사용자는 최대 4분을 기다려야 하므로 취소·안내가 필요합니다.

### 실제 검증 상태 (2026-11-23)

- 합성 질문 `지난주 배포 얘기 찾아줘`의 실제 연결 함수 1회: HTTP 200·13,109ms, `배포`와 서울 시간 지난주 월요일~월요일 범위를 확인했습니다. DB 검색 결과를 검증한 것은 아닙니다.

- 공용 CONTRACTS에 E-4의 상세 API 규격은 아직 없으므로 위 경로·필드·조회 범위·기한 형식 확정을 요청합니다. 공용 문서는 직접 바꾸지 않았습니다.
